# 基于分子指纹与描述符的脂溶性（logD）预测

**提交分支：`zhangqiyue`（自建分支，未改动 `main`）**

本仓库基于 MoleculeNet 的 Lipophilicity 数据集，从零搭建了一条可复现的
SMILES → logD 回归流程：数据体检与清洗 → 分子特征化 → scaffold 划分 →
线性基线 → 改进模型 → `test.csv` 一键预测接口。全部实验在 CPU 上完成。

---

## 1. 任务简介

**任务**：给定一个分子的 SMILES 字符串，预测它在 pH 7.4 条件下辛醇/水分配系数的
对数值（logD）。数值越大，分子越倾向进入脂相，是药物发现中评估吸收与成药性的常用指标。
这是一个单任务回归问题。

**数据**：仓库根目录 `Lipophilicity.csv`，4200 行，三列
`CMPD_CHEMBLID`（编号）、`exp`（logD 标签）、`smiles`（分子结构）。

**评测口径**：按 Murcko 骨架（scaffold）划分训练/验证/测试集，主指标 RMSE。
骨架划分保证测试集里的分子骨架在训练时完全没见过，测的是对新骨架的泛化能力。

**我实际完成的工作**：

1. 数据体检，定位出 8 行异常、410 行完全重复、2 组标签矛盾，清洗后得到 3780 条可用样本；
2. 特征化：Morgan 指纹（ECFP4，2048 位）+ 12 个分子描述符；
3. Baseline：12 个描述符 + Ridge 回归，测试集 RMSE **0.976**；
4. 改进模型：指纹 + 描述符拼接 + 梯度提升树，测试集 RMSE **0.807**（较基线改善 17.3%）；
5. `test.csv` 一键预测接口，遇到空/非法/超长 SMILES 不崩，输出逐行状态与失败原因；
6. 全流程脚本化，一条命令可从原始 CSV 复现到最终指标。

## 2. 数据集检查与预处理

**结论：原始数据不能直接拿来训练。** `src/01_check_data.py` 的体检结果如下。

| 问题 | 数量 | 具体位置 / 处理 |
| --- | --- | --- |
| 标签为空 | 1 | `CHEMBL_BLANK_EXP`（第 3792 行），剔除 |
| 标签不是数值 | 1 | `CHEMBL_BAD_EXP_TEXT` = `definitely_wrong`，剔除 |
| 标签量级异常 | 1 | `CHEMBL_BAD_EXP_EXTREME` = `999999.0`，剔除 |
| SMILES 为空 | 1 | `CHEMBL_BLANK_SMILES`，剔除 |
| SMILES 无法被 RDKit 解析 | 2 | `CHEMBL_RDKit_FAIL_1` = `C1(CC`（括号不闭合）、`CHEMBL_RDKit_FAIL_2` = `not_a_smiles`，剔除 |
| SMILES 超长 | 2 | `CHEMBL_HUGE_1`（6000 字符）、`CHEMBL_HUGE_2`（4612 字符），剔除 |
| 三列完全重复 | 410 行 | 去重 |
| 按结构重复 | 415 行 | 按 canonical SMILES 去重，保留首条 |
| 同一结构标签矛盾 | 2 组 | `CHEMBL325713`（0.96 / -1.03）、`CHEMBL1201753`（0.91 / 3.44），保留首条 |
| ID 格式不规范 | 1 | `ljiohohoihoa` 是乱码 ID，但分子和标签都正常，**保留** |

**清洗规则**（`src/02_clean.py` 中的常量，改数据可直接复用）：

1. `exp` 必须能转成数值，且 `|exp| <= 10`（logD 的合理量级）；
2. `smiles` 不能为空；
3. `smiles` 长度不能超过 **300 字符**——清洗后数据里最长的有效 SMILES 是 267 字符，
   超长的一律在**解析之前**拦掉；
4. `smiles` 必须能被 RDKit 解析；
5. 按 canonical SMILES（`Chem.MolToSmiles`）去重，保留原始顺序里的第一条。

**处理结果**：`4200 行` → 剔除 8 行异常 → `4192 行` → 去重 412 行 → **`3780 行`**。
清洗后标签区间 -1.50 ~ 4.50，中位数 2.36，标准差 1.20。

> 第 3 条规则不是保守，是必须的：RDKit 解析 6000 字符的纯碳链时递归爆栈，
> 整个 Python 进程直接崩溃（退出码 `0xC00000FD`），`try/except` 抓不到。
> 所以在把 SMILES 交给 RDKit 之前必须先按长度过滤。

原始数据保留在仓库根目录未改动，清洗产物写入 `data/clean.csv`（由脚本生成，未入库）。

## 3. 分子表示与输入处理

分子被转成两类互补的数字特征（实现统一在 `src/featurize.py`）：

**（1）Morgan 指纹（ECFP4）**：半径 2、2048 位。每个位代表一种分子局部子结构
（原子 + 半径 2 以内的邻居环境），出现即置 1。它回答的是"这个分子里有没有某类局部片段"。

- 3780 个分子平均激活 **48.6** 个位（共 2048 位），非常稀疏；
- 指纹对同一子结构的编号稳定，因此可以跨分子比较。

**（2）12 个分子描述符**：`MolWt`、`MolLogP`、`TPSA`、`NumHDonors`、`NumHAcceptors`、
`NumRotatableBonds`、`RingCount`、`NumAromaticRings`、`FractionCSP3`、`HeavyAtomCount`、
`NumHeteroatoms`、`BertzCT`。它们回答的是"这个分子整体有多重、多油、多极性"，
对 logD 这种亲疏水性标签有直接解释力。

**格式转换**：SMILES → `RDKit Mol` → 指纹位向量 / 描述符浮点数 → `numpy` 数组，
按行对齐保存为 `data/X_morgan.npy`（3780×2048）、`data/X_desc.npy`（3780×12）、
`data/y.npy`（3780）。

**计算设备**：全部在 **CPU** 上完成。RDKit 的特征化是单线程的，3780 个分子只需数秒，
没有走 GPU 的必要；sklearn 的树模型训练同样在 CPU 上，九组模型搜索总耗时约 52 秒。

**速度优化**：

- 特征只算一次、存成 `.npy`，后续所有模型直接读数组，不重复解析 SMILES；
- 描述符的缺失值**不在特征化阶段填补**，而是留给模型 pipeline 用训练集的中位数填补，
  避免验证集/测试集信息泄漏；
- 超长 SMILES 在解析前拦截，既是正确性问题，也避免了几千原子分子拖慢整个流程。

## 4. Baseline 模型

**Baseline = 12 个描述符 → 中位数填补 → 标准化 → Ridge 回归（L2 正则线性回归）。**

选择它的理由：

1. **最简可比**：只用 12 个已解释清楚的物化性质，没有任何指纹/图结构信息，
   是"只靠整体性质能预测到什么程度"的下限；
2. **训练稳定**：闭式解，秒级完成，结果不依赖随机种子；
3. **可解释**：系数直接对应描述符，能看出哪些性质与 logD 相关；
4. **给出对照线**：后面任何复杂模型必须明显低于它，否则说明复杂度没换来收益。

同时跑了一个"永远预测训练集均值"的哑模型作为最低参照（它的 RMSE 就等于标签标准差，
R² 恒为 0），确保 baseline 本身确实学到了东西。

**结果**：alpha 在验证集上从 `[0.01, 0.1, 1, 10, 100]` 中选出 **10**。
训练 RMSE 1.030 / 验证 1.040 / 测试 **0.976**，测试 R² **0.360**，
比均值基线（测试 RMSE 1.224）好 **20.3%**。

## 5. 文献启发与模型设计

我参考了三篇工作，只各取一点，不追求复现：

| 文献 | 借鉴的点 | 如何简化落地 |
| --- | --- | --- |
| Wu et al., *MoleculeNet: a benchmark for molecular machine learning*, Chemical Science, 2018 | 这个数据集的标准评测方式：**按 scaffold 划分**、以 RMSE 为主指标 | 用 Murcko 骨架分组划分，8:1:1，固定种子 42；实测随机划分会让 134 个骨架同时出现在训练和测试集里 |
| Rogers & Hahn, *Extended-Connectivity Fingerprints*, J. Chem. Inf. Model., 2010 | ECFP 的**半径与位数选择**：半径 2 覆盖原子的两跳邻域，2048 位在碰撞率与维度间折中 | 直接采用半径 2 / 2048 位的 Morgan 指纹，作为固定半径的局部子结构编码 |
| Yang et al., *Analyzing Learned Molecular Representations for Property Prediction*（Chemprop）, J. Chem. Inf. Model., 2019 | 核心思想是**让模型自己学分子局部环境的表示**（消息传递），而不是只用全局描述符 | 没有上 GNN（时间与算力不够），而是用"局部子结构指纹 + 全局描述符"喂给梯度提升树，用固定半径的指纹近似"局部环境编码" |

**设计逻辑**：文献给出的关键提示是"分子局部结构信息比整体描述符更有表达力"，
但直接把 2048 位高维稀疏指纹喂给线性模型会失效（实测 Ridge 在纯指纹上验证 RMSE 1.314，
比只用 12 个描述符的 1.040 更差）。因此最终采用**两类特征拼接 + 树模型**：
树模型能在高维稀疏的 0/1 特征上做非线性切分，也天然处理特征间的交互。

## 6. AI 辅助过程

**使用的工具**：VS Code（写代码、跑终端）+ 豆包（AI 助手，用于生成脚本骨架、排查报错、整理文档）。
Codex 扩展装在编辑器里，但本项目实际未用它生成代码。

**AI 完成了哪些内容**：

- `src/` 下全部脚本的初版骨架（体检、清洗、特征、划分、训练、预测接口）；
- 各步骤的报告模板（`reports/*.md`）与 README 初稿；
- 报错排查：RDKit 解析超长 SMILES 导致的进程崩溃、BLAS 加载错误导致的训练崩溃。

**prompt 是怎么设计的**（提高可靠性的关键）：

1. **先给事实，再要方案**：先把数据的列名、样本量、可疑行贴给 AI，而不是只问"怎么做 Lipophilicity"；
2. **要求可验收**：明确要求"每条命令后面写清预期输出"，这样 AI 给的每一步都能当场判断对错；
3. **禁止编造数字**：要求所有数字必须来自实际运行的输出，不许凭印象写；
4. **分步确认**：按"体检 → 清洗 → 特征 → 划分 → 基线 → 改进 → 接口"逐段推进，每段跑通再进下一段，
   避免一次性生成长代码后无法定位错误；
5. **要求自检**：让每个脚本在结束前自己校验（行数、唯一性、取值范围），不通过就非零退出。

**如何核查 AI 的输出**：

- 每个脚本都内置自检断言，跑完打印"通过/未通过"，未通过直接 `raise SystemExit(1)`；
- 关键数字手工复核：例如 `4200 − 8 = 4192`、`4192 − 412 = 3780`，
  与 `reports/data_check.md`、`clean_log.md` 三处数字互相印证；
- 独立重跑：清洗、特征、划分、训练各自单独执行一遍，确认结果与报告中一致；
- 对 AI 给出的"结论"逐条找证据：例如"随机划分会造成骨架泄漏"这一定性说法，
  用脚本实测出 134 个共享骨架后才写进文档；
- AI 写的文字我逐段读过，改掉了与实际结果不符的表述（例如最初把"2 组标签矛盾"写成了 3 组，
  查证后发现第 3 组是 999999 这个坏标签造成的假象）。

**责任声明**：代码与文字有 AI 参与生成，但每一条结论都在本机实际运行验证过，
我对仓库内容的正确性负责。

| matplotlib | 3.10.9 |

CPU：本机多核 CPU，无 GPU。九组模型搜索约 52 秒，特征化在秒级完成。

**数据划分**：Murcko 骨架分组划分，目标 8:1:1，随机种子 42。

| 集合 | 样本数 | 骨架数 |
| --- | --- | --- |
| 训练 | 3024 | 1464 |
| 验证 | 378 | 378 |
| 测试 | 378 | 378 |

全数据共 2220 个骨架。作为对照，同样比例的随机划分会让训练集与测试集共享 **134** 个骨架；
骨架划分下为 **0**。

**模型与超参**：

- Baseline：`Ridge(alpha=10)` on 12 descriptors（alpha 由验证集选择）；
- 改进：`HistGradientBoostingRegressor(max_iter=250, learning_rate=0.06, max_leaf_nodes=31,
  min_samples_leaf=20, l2_regularization=0.1, random_state=42)`；
- 特征预处理：`SimpleImputer(median)` + （线性模型额外）`StandardScaler`；
- 搜索空间：3 套特征（描述符 / 指纹 / 两者拼接）× 3 种模型（Ridge / RandomForest / HistGB），
  共 9 组，全部只在训练集拟合，用**验证集 RMSE** 选型。

**评价指标**：RMSE 为主（与标签同量纲，便于解释），辅以 MAE 和 R²。
测试集只在最终选型确定后评估一次，不参与任何调参。

**如何判断好坏**：三层对照——① 必须显著优于均值基线（R² > 0）；
② 必须优于 12 描述符 Ridge 基线；③ 增益必须与新增信息量相称——
特征从 12 维增到 2060 维，误差下降 17.3%，说明增益确实来自信息而不是单纯的维度膨胀。
另外测试集只在最终选型确定后评估一次，避免"看测试集调参"造成的乐观偏差。

## 8. 实验结果与分析

### 8.1 九组模型搜索（验证集 RMSE）

| 特征 | 特征数 | Ridge | RandomForest | HistGB |
| --- | --- | --- | --- | --- |
| 只有描述符 | 12 | 1.040 | 0.944 | 0.943 |
| 只有指纹 | 2048 | 1.314 | 1.008 | 0.949 |
| 描述符 + 指纹 | 2060 | 1.199 | 0.894 | **0.819 ← 选中** |

### 8.2 最终测试集结果

| 模型 | 测试 RMSE | 测试 MAE | 测试 R² |
| --- | --- | --- | --- |
| 均值基线 | 1.224 | — | 0.000 |
| Baseline（描述符 + Ridge） | 0.976 | 0.786 | 0.360 |
| **改进（描述符 + 指纹 + HistGB）** | **0.807** | **0.613** | **0.562** |

相对 baseline 改善 **17.3%**，相对均值基线改善 **34.1%**。

### 8.3 结论

1. **指纹单独使用反而更差**。2048 位里平均只激活 48.6 位，3024 个训练样本撑不起这么高维的
   稀疏特征，Ridge 直接退化到 1.314。这和"指纹一定更好"的直觉相反。
2. **两类特征互补**。整块打乱实验（把某一块特征的行随机打乱，看验证集 RMSE 涨多少）：
   打乱描述符 → RMSE 从 0.819 涨到 **1.419**（+0.60）；打乱指纹 → 涨到 **1.177**（+0.36）。
   描述符信息更集中、更不可替代；指纹提供描述符给不出的局部结构信息。
3. **线性模型撑不住高维 0/1 特征**。2060 维拼接特征上 Ridge 的训练直接报
   `LinAlgWarning: Ill-conditioned matrix`，这正是改用树模型的实测理由。
4. **测试集分数只评了一次**，选型全程只看验证集，这个 0.807 是干净的成绩。

### 8.4 目前的主要问题

1. **两端被压缩，向中间回归**：低值区系统性高估、高值区系统性低估，实测数据见本节末尾的分箱表。
2. **高维稀疏 + 小样本**：2048 位指纹在 3024 个样本上有效信息密度低，很多位几乎恒为 0。
3. **没有用图神经网络**：Chemprop 一类的消息传递模型能在 4200 条量级上带来提升，
   但需要 PyTorch/GPU 与更长训练时间，本次未做。
4. **数据本身有噪声**：原始数据存在 2 组同结构但标签差异很大的样本（0.96 vs -1.03），
   测试集 RMSE 里有一部分是无法消除的标签噪声。
5. **没有做深度调参**：HistGB 的参数是经验值，仅做了小范围网格，没有系统搜索。

**两端偏差的实测数据**（测试集按真实值分箱，`reports/improved.md` 第 4 节由脚本输出）：

| 真实 logD 区间 | 样本数 | 真实均值 | 预测均值 | 偏差 |
| --- | --- | --- | --- | --- |
| < -0.5 | 12 | -0.92 | 0.48 | **+1.40** |
| -0.5 ~ 1.0 | 49 | 0.48 | 1.22 | +0.74 |
| 1.0 ~ 2.5 | 115 | 1.75 | 1.94 | +0.19 |
| 2.5 ~ 3.5 | 147 | 2.97 | 2.75 | -0.22 |
| > 3.5 | 55 | 3.85 | 2.92 | **-0.93** |

预测值对真实值的回归斜率只有 **0.548**（理想为 1），相关系数 0.75；预测范围 -0.22 ~ 3.84，
真实范围 -1.42 ~ 4.50。低值区高估、高值区低估，是树模型对训练集中稀少的极端样本不敢外推的典型表现。

### 8.5 如果要继续做

优先补 GNN（Chemprop 简化版）或 fingerprint + kernel 方法（如 SVM/GPR），
并针对极端值做样本加权或分区间建模。
